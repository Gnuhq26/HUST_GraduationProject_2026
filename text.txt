TÀI LIỆU KIẾN TRÚC: TÍNH NĂNG IMPORT EXCEL SẢN PHẨM
1. Luồng hoạt động chính (2-Phase Import)
Phase 1 - Preview: User upload file -> Backend đọc (Parse) -> Validate (Cú pháp & DB) -> Trả về kết quả phân tích (Số dòng đúng, số dòng lỗi, chi tiết lỗi) -> KHÔNG ghi vào DB.

Phase 2 - Commit: User xác nhận -> Frontend gọi API Commit (gửi lại file) -> Backend đọc lại file, chỉ lấy những dòng được xác nhận là "Pass" -> Dùng Prisma Transaction ghi vào DB -> Trả kết quả cuối cùng.

2. Thiết kế Backend (NestJS + Prisma + ExcelJS)
Các API Endpoints (Trong ProductImportController):

GET /products/import/template: Trả về file .xlsx mẫu.

POST /products/import/preview: Nhận multipart/form-data (file excel), trả về JSON thống kê lỗi.

POST /products/import/commit: Nhận lại file excel, thực hiện ghi DB.

Cấu trúc thư mục (Tách biệt trách nhiệm - SOLID):

product-import.parser.ts: Chuyên dùng exceljs để đọc từ dòng 2 (bỏ header), chuẩn hóa text (trim, ép kiểu).

product-import.validator.ts: Xử lý 2 lớp:

Lớp 1 (Syntax): Thiếu tên, giá tiền bị âm, sai định dạng.

Lớp 2 (Logic DB): BẮT BUỘC gắn where: { storeId } để check xem Mã danh mục, Mã NCC có tồn tại trong cửa hàng này không.

product-import.service.ts: Chứa logic tổng và gọi Prisma. Sử dụng prisma.$transaction chứa danh sách các lệnh prisma.product.upsert() (Nếu trùng mã thì update giá/tồn kho, nếu chưa có thì create mới).

3. Thiết kế Frontend (React/Vue/Angular)
UI/UX: Màn hình Modal có 3 bước (Download Template -> Upload File -> Preview & Confirm).

Preview Table: Hiển thị dạng lưới. Những dòng bị lỗi tô nền đỏ, cột cuối cùng ghi rõ "Lý do lỗi" (VD: Thiếu giá bán, Danh mục không tồn tại).

Action: Khi user bấm "Xác nhận Import", gọi API /commit và hiển thị Toast/Noti thành công.
